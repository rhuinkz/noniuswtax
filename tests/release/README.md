# NONIUSWTAX — One Full Release Verification Package

**One command. Four integrated stages. One consolidated HTML/JSON report.** This package runs in a disposable local Docker environment with fictional data and does not call Hostinger, read production databases, or require paid cloud-testing services.

## Run it on Windows

Open GitHub Desktop on branch `test/local-one-command-release-suite`, **Fetch origin → Pull origin** to get the updated package. With Docker running, open PowerShell in the repository folder and execute:

    powershell -ExecutionPolicy Bypass -File .\tests\release\run-all.ps1

Linux/WSL2 with Docker Engine and Compose:

    bash tests/release/run-all.sh

Each script builds PHP 8.4/Apache, MariaDB 11.4 and the pinned Chromium Playwright browser, creates an isolated empty database, executes all stages, collects results, then removes **only** its dedicated release-test Docker containers and volume. A failure in one test stage does not automatically suppress unrelated stages.

## Four stages inside the same command

| Stage | Included verification |
|---|---|
| 1. Source and finance math | PHP lint, JavaScript checks, existing safety and calculation smoke, **13 independent decimal golden cases**, SQL console query guard. The fixture's rates/formulas are synthetic and require separate professional BIR review. |
| 2. Real application + browser | Fresh installation; login/invalid credentials; roles, CSRF and school isolation; MariaDB migration and trigger inventory; monthly record locks; append-only audit; School Draft → Submit → Division Check; checked certificate seal; internal HTTP denials. |
| 2. PDF/volume and capacity probe | Browser downloads **an actual Form 2307 generated by the application** using locally bundled pdf-lib; saves the PDF and a first-page PNG preview. Inserts **10,000 synthetic transactions**, runs 30 parallel API requests and records p95 timing. This is not a 1,000-user load certification. |
| 3. Backup/restore | Full `mariadb-dump` including data and triggers, restore into a **second disposable database**, compare table/trigger counts, verify protected audit and closed-month transaction edits are rejected after restore. |
| 4. Consolidated report | One automatically generated summary of PASS/FAIL for technical checks and clearly distinguished PENDING approvals. |

## Open these files after the run

- **Main report:** `test-results/release-report.html`
- **Main JSON:** `test-results/release-summary.json`
- Playwright detailed report: `test-results/html/index.html`
- Playwright raw JSON: `test-results/results.json`
- PDF generated from a checked synthetic transaction: `test-results/bir2307-rendered-synthetic.pdf`
- Printable visual-review image: `test-results/bir2307-visual-review.png`
- MariaDB restore evidence: `test-results/backup-restore.json`
- Local performance data: `test-results/performance.json`

The scripts invalidate previous run's summary/evidence files to prevent reporting stale PASS results. Archive previous outputs separately if needed. Failing stages are reflected in the summary; never suppress integrity failures.

## Production approval remains separate

The one-command package is automated technical testing, **not an approval authority**. The consolidated report always marks production release PENDING until authorized personnel sign off on: Philippine BIR/ATC/VAT/EWT rules and rounding; actual printed Form 2307; upgrade/rollback on a sanitized copy of a real deployment; Hostinger web-server and credential security; actual target concurrency under an agreed p95 target; signed/verified release artifact and change authorization.

See `docs/RELEASE_ACCEPTANCE_GATE.md`. Preserve the real PDF and preview for finance/records visual review. The package's mathematical golden cases independently check arithmetic *under the implemented formula*, but do not prove that the formula or selected rates conform to Philippine tax law.

## Safety, billing, and prerequisites

- MariaDB TCP is not exposed on Windows; local app binds to `127.0.0.1:8877` only. Docker Compose project uses the dedicated name `nonius-release-verification`.
- All credentials, schools and transactions in this suite are synthetic. Docker's `.dockerignore` excludes deployment secrets, runtime data, archives and SQL exports.
- This uses local resources; Docker images and npm packages need Internet/download bandwidth initially and disk space, but no paid remote test infrastructure.
- Docker Desktop free usage depends on its licensing category. In particular, **government-entity use may require a paid subscription** even when personal/educational uses are free. Check https://docs.docker.com/subscription-billing/desktop-license/ . An open-source Docker Engine installation in Linux/WSL2 is the alternative.
- Recommended test PC: at least 8 GB RAM available to Docker, SSD storage, and enough disk space for images and test artifacts. These are estimates, not hard prerequisites.
- The suite is **newly expanded and unverified end-to-end on the user's Windows Docker**. Pull the branch and run locally; a failed category indicates further review or a test fix is required.
